# Mio Graph examples

Each `.miog` file compiles to one Mio source file in the same directory.

| File | Kind | Demonstrates |
| --- | --- | --- |
| `score_report.miog` | program | variables, constants, arithmetic, nested data flow, `Sequence`, `Branch`, `chant`, `Return` |
| `square.miog` | function | function `Entry` parameters, `Multiply`, `Return` |

## Generate Mio source

1. Open a `.miog` file in VS Code.
2. Run **Mio Graph: Generate Mio Source** from the Command Palette.
3. The extension writes `score_report.mio` / `square.mio` next to the graph,
   opens it, and validates it with `mio check` when the Mio CLI is configured.

The command never silently overwrites a file that was not generated by Mio
Graph; it asks for confirmation first. Generated files start with
`// Generated by Mio Graph` and are meant to be regenerated, not edited.

From a terminal with a Mio CLI:

```bash
mio check score_report.mio
mio run score_report.mio
```

`score_report.mio` prints:

```text
passed
154
```

`square.mio` declares `waza square(value: int64) -> int64`; add a caller in a
scratch copy to run it:

```mio
chant(square(7)); // 49
```

## Expected `score_report.mio`

```mio
// Generated by Mio Graph. Do not edit this file by hand.
// Graph: score_report (version 1)

waza mio_graph_main() -> unit {
    kaku score: int64 = 72;
    kaku passing: int64 = 60;
    kaku message: string = "failed";
    kaku bonus: int64 = 0;
    kaku total: int64 = 0;
    bonus = score + 5;
    total = bonus * 2;
    moshi (score > passing) {
        message = "passed";
        chant(message);
        chant(total);
        kaesu;
    } sore {
        chant(message);
        kaesu;
    }
}

mio_graph_main();
```

## Reading the graph JSON

- `nodes[].params` carries the semantic data (variable name, literal, function
  name). Pins are derived from the node type and are not required in the file.
- `connections[]` reference `nodeId` / `pinId` pairs such as
  `entry.exec_out -> seq.exec_in`. Exec connections define statement order.
- `metadata.variables` must declare every variable used by `VariableGet` and
  `VariableSet`, including a typed `initialValue`.
- `metadata.imports` and `metadata.functions` describe external functions used
  by `FunctionCall` nodes. See `docs/MIO_GRAPH.md` for the full format.
